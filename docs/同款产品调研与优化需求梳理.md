# 工作量评估工具 · GitHub 同款产品调研与优化需求梳理

> 调研日期：2026-09-26 ｜ 调研方式：GitHub / 行业标准公开资料检索 + 本工具代码与迭代记录比对
> 结论先行：本工具在「需求文档 → 功能点明细 → 母版成品表」这条主链路上的自动化程度（docx 识别 + AI 增强 + 母版保真填充）**强于调研到的所有开源同类**；差距集中在 **可视化、历史与对比、多格式导出、标准法（NESMA/GB 36964 方程法）、协作与主题** 五个方向。

## 1. 本工具现状速览（作为差距分析的基准）

**主链路**：上传需求 docx → 规则识别 + 大模型增强 → 人工复核功能点（EI/EO/EQ/ILF/EIF × 重用度/修改类型）→ 生成母版成品 xlsx（IFPUG 105.07 口径）；旁路为 PERT 三点估算（项目库 + AI 拆分 + 文档暂存触发）。

**已具备**（部分来自近期迭代 T00927~T00963）：
- 生成进度条（后台真实阶段上报 + 轮询 + 超时兜底 + 失败/超时恢复）
- Excel 公式缓存后台补算（async/sync/off 策略可配）+ 卡死按 PID 定向回收
- 配置中心：LLM 多厂商、项目上下文目录、更新源、公式缓存策略
- 断点续录草稿、首访引导、更新检测与一键更新、PERT 项目库

**已知短板**：前端为单文件内联实现（无组件化）；仅 xlsx 一种产出；无图表可视化；无历史版本对比；无暗色主题/主题定制；识别规则硬编码；无自动化测试；单人单机，无协作。

### 2.5 行业标准（非 GitHub，但是国内市场的"功能扩展"硬需求）

- **GB/T 36964-2018《软件工程 软件开发成本度量规范》方程法**：`软件开发成本 = (软件规模 × 生产率 PDR) × 软件因素调整因子 SWF × 开发因素调整因子 RDF × 人力成本费率 + 直接非人力成本`
- **NESMA 三种计数法**（GB/T 42588-2023）：预估法 `35×ILF+15×EIF`、估算法 `7×ILF+5×EIF+4×EI+5×EO+4×EQ`、指示法——立项/招投标准备阶段常用，**无需逐条明细**
- **CSBMK 中国软件行业基准数据**：功能点单价（约 1336 元/FP）、P50 生产率（6.96 人时/FP）、需求变更调整因子（预算 1.70 → 设计 1.00）、业务领域因子（金融 1.67、政务 1.15 等）、开发因素因子（语言/团队背景 0.6~1.5）
- IFPUG 4.x / COSMIC / FiSMA / MkII 均已形成国标（GB/T 42448/42449/42452/42566-2023）

> 结论：国内客户（银行/政企）的造价评审口径正在向 GB/T 36964 + CSBMK 靠拢，这是本工具**最值得投入的功能扩展**，也是开源同类完全没有覆盖的空白。

## 4. 优化需求清单

优先级：**P0** = 直接影响可用性/核心价值，先做；**P1** = 明显提升竞争力；**P2** = 锦上添花。
规模：S ≤ 1 天，M = 2~5 天，L > 1 周（单人）。

### A. 客户体验提升

| 编号 | 需求 | 现状与痛点 | 对标 | 方案要点 | 优先级/规模 |
|---|---|---|---|---|---|
| UX-01 | **估算历史与一键重开** | IFPUG 估算完成后仅留下成品 xlsx，无法从应用内回看/重算/续改 | FunctionPoint 历史管理 | 生成时把候选清单 + 参数 + sid 落库（沿用 PERT 的 SQLite 模式），历史页支持「重开→复核→重新生成」「另存为」 | **P0** / M |

## 5. 建议路线图

**第一阶段（体验补课，约 2~3 周）**
UX-01 历史与重开、UX-02 结果页图表、UX-04 复核表格体验、TH-01 暗色主题（依赖 UI-01 令牌梳理）、ENG-02 核心链路测试。
→ 验收口径：任意一次历史估算可在 3 次点击内重开并重算；结果页一屏给出图表结论；暗色下全页面无对比度硬伤。

**第二阶段（行业差异化，约 3~4 周）**
FE-01 NESMA 预估/估算法、FE-02 GB/T 36964 方程法造价、FE-03 基准数据与费率配置、FE-07 阶段变更因子、UX-03 多格式导出。
→ 验收口径：同一份需求 docx 可同时产出「IFPUG 母版成品表」与「GB/T 36964 造价测算表」，因子取值与依据可追溯，可导出 PDF/CSV。

## 6. 风险与依赖

1. **Excel COM 依赖**：公式缓存补算已异步化 + 超时回收（T00930/60），但成品表本身仍依赖 Excel 打开重算；若脱离 Excel 环境交付，需要预计算方案或引导用户开启自动重算。
2. **AI 识别质量**：依赖需求文档书写质量（FunctionPoint 同样声明此限制）；驳回流（UX-05）+ 规则沉淀（FE-09）是长期提准手段。
3. **国标因子更新**：CSBMK 基准数据逐年更新（功能点单价、P50 生产率），FE-03 必须做成"数据与代码分离"，否则每年都要发版。
4. **母版口径**：现母版为特定客户口径（105.07 金标准）；FE-08 多模板会引入列映射复杂度，建议在 ENG-01 拆分后再做。
5. **单人开发节奏**：上表总规模约 8~12 周（单人满负荷），建议严格按 P0 → P1 切片交付，每片保持"可发布"。
