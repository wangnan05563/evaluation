# 工作量评估自动化系统 概要设计说明

> 版本：V0.1　|　依据：《工作量评估自动化实现方案.md》　|　路线：**方案A**（AI 识别 + 人工确认 + 自动套表）

---

## 一、概述

### 1.1 定位
面向造价评估人员的**半自动**辅助工具：上传需求说明书（docx）→ AI 识别功能点候选清单 → 人工确认/修订 → 引擎按 IFPUG 计数 → 套用成品模板（`副本造价评估…xlsx`）生成最终造价表并下载。

### 1.2 范围
- **输入**：需求说明书（docx，暂定中文）
- **输出**：成品工作量评估表（xlsx，4 个 Sheet 结构与原模板一致）、候选清单 JSON/Excel、校验报告
- **不做**：全自动无审核出表、报价审批流转、移动端适配

### 1.3 术语
| 术语 | 含义 |
|---|---|
| 功能点 | IFPUG 五类：ILF / EIF / EI / EO / EQ |
| UFP | 未调整功能点（按复杂度矩阵加权） |
| US | 规模明细（`UFP × 重用系数 × 修改系数`） |
| 候选清单 | AI 识别出的待人工确认功能点集合 |

## 二、总体架构

```
浏览器（前端交互页面）
   │  HTTP/本地脚本
   ▼
┌──────────────────────────────┐
│         应用服务层            │
│ 01 需求解析器  02 功能点识别   │
│ 03 规则引擎     04 模板生成器  │
│ 05 参数库       06 审核清单   │
└──────────────┬───────────────┘
               │
    ├── 输入 docx（需求说明书）
    └── 输出 xlsx / json / 校验报告
```

**部署形态**：首期采用**本地 Python 引擎 + 浏览器交互界面**（前端调用本地服务或脚本），不依赖公网。页面与引擎通过 JSON 交互。

## 三、模块划分（对应方案第五章）

| 编号 | 模块 | 职责 | 关键技术 |
|---|---|---|---|
| M1 | 需求解析器 | docx → 结构化章节/表格/清单片段 | python-docx |
| M2 | 功能点识别 | 片段 → 功能点候选（类别/维度/重用/修改） | LLM + Prompt |
| M3 | 规则引擎 | 复杂度矩阵、权重、VAF、工作量/费用计算 | 纯 Python |

| M5 | 参数库 | 系数/因子常量，声明式可改 | config |
| M6 | 审核清单 | 候选清单核验、修订、回灌引擎 | JSON/Excel |
| M7 | 前端交互页 | 上传→审核→预览→下载 | 浏览器页面 |

## 四、前端交互页面设计

### 4.1 页面清单

| 页面 | 路径 | 用途 |
|---|---|---|
| P1 上传页 | `/upload` | 选择/拖拽需求 docx，配置项目参数 |
| P2 候选清单审核页 | `/review` | 逐条展示 AI 识别功能点，人工确认/修改（核心页） |
| P3 结果页 | `/result` | 预警校验项、预览规模/工作量/费用汇总、下载成品 |

### 4.2 页面流程

```
P1 上传   →  P2 审核  →  P3 结果
  │            │  (确认后)      │  (下载xlsx)
  项目参数     修正类别/维度     汇总卡片+校验告警
  开始识别     确认通过
```

- P1 → P2：提交后调 M1+M2，返回候选清单
- P2 → P3：确认清单，调 M3+M4 生成成品；携带校验报告
- P3：分系统/分模块看明细分，一键下载 xlsx

### 4.3 视觉规范（遵循用户偏好）
- 清爽明亮**扁平化**，**马卡龙色系**（浅粉 + 浅青主色，白底）
- **大圆角**卡片、轻微**磨砂玻璃**质感、柔和浅色投影
- 圆润字体、温馨亲切；可爱**卡通机器人 IP** 插画（引导/空状态/完成态）
- 端到端流程用**对话气泡/步骤条**呈现，降低评估人员学习成本

### 4.4 关键交互
- P1：支持拖拽上传；上传后即时回显章节树与识别状态
- P2：按「系统 → 模块」分组树；每条可改类别、复杂度维度、重用、修改类型；**判定依据**可展开查看（便于审计）；顶部实时显示 UFP 估算
- P3：规模/工作量/费用三档（下限/中值/上限）卡片；校验告警列表；成品下载

## 六、接口定义（页面 ↔ 引擎）

| 接口 | 方法 | 入参 | 出参 |
|---|---|---|---|
| `POST /parse` | 解析数量 | 文档路径 | 章节片段、识别进度 |
| `POST /recognize` | 识别 | 片段 / 项目参数 | 候选清单 JSON |
| `POST /confirm` | 确认 | 正式清单 | 复核摘要 |
| `POST /calculate` | 计算 | 正式清单、参数 | 汇总结果（分系统） |
| `POST /generate` | 生成 | 结果 | 成品 xlsx 路径、校验报告 |

> 首期可改为**本地脚本 + 命令行/回调**实现，页面仅做展示与确认，接口语义保持一致。

## 七、规则引擎计算口径（与 Excel 公式对齐）

1. 复杂度矩阵：ILF/EIF 用 `RET×DET`；EI 用 `FTR×DET`；EO/EQ 用 `FTR×DET`（三套阈值）
2. 权重：ILF 7/10/15、EIF 5/7/10、EI 3/4/6、EO 4/5/7、EQ 3/4/6
3. `US = UFP × 重用系数 × 修改系数`（重 0.33/0.67/1.0；修 1.0/0.8/0.2）
4. 调整后规模 = 累加 UFP × 规模变更因子（早 1.39 / 中 1.21 / 晚 1.10 / 交付后 1.00）
5. 工作量 = 调整后规模 × 生产率(8.54/10.67/12.80) ÷ 8；× 调整因子链
6. 费用 = 工作量 ÷ 22 × 人月单价（2.57 万）

## 八、质量标准

- 单测：复杂度矩阵边界、链路与母版公式偏差 < 0.1%
- 金标准：样本项目 UFP=234 / US=105.07，驱动回归
- 识别评价：对样本需求，类别查全/查准 ≥ 80% 后进人工确认环节

## 十一、端到端验证与实现进展

已实现的工具链（`scripts/`）：
| 脚本 | 模块 | 作用 |
|---|---|---|
| `parse_requirements.py` | M1 | 抽取 docx 章节树与候选线索 |
| `build_candidates.py` | M2 | 从功能清单表抽候选并给 IFPUG 类型初判 |
| `engine.py` | M3 | 规则引擎（US/工作量/费用，口径同母版） |
| `generate_xlsx.py` | M4/M6 | 套母版生成成品、金标准校验 |
| `inspect_template.py` | - | 读取母版公式，供保真依据 |

**金标准校验（已通过）**：用母版既有 45 条明细原样重建，引擎复算 `US = 105.07`，
并沿费用链路复现 `127.13 FP → 108.52/135.65/162.78 人天 → 12.68/15.85/19.02 万元`，
与《费用估算》逐格一致（偏差 < 0.1%）。母版两个技术要点已沉淀进引擎：
- 类别默认 UFP：ILF10 / EIF7 / EI4 / EO5 / EQ4
- 重用系数精确值：高=1/3、中=2/3（不能用 0.33/0.67 近似）

**前端**：`frontend/index.html` 为马卡龙风格三页交互原型（上传 → 审核 → 结果/下载）。

**边界说明**：桌面样本《综合服务平台需求说明书》的功能清单表为**空占位表**（仅编号1-8），
真实功能点需基于正文（94 张表 × 文本）逐模块 LLM 语义识别，属后续「识别优化」阶段，
本轮已完成**链路打通 + 生成器保真 + 规则口径校准**。
