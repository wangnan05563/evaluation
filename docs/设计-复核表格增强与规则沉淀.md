## 2. 现状盘点（设计依据）

## 3. 复核表格增强（FR-1.4）

1. **排序**：表头点击排序（描述/类型/US/seq 四列），`sortState={key,dir}` 作用于渲染副本（items 原序不动，seq 引用稳定）；表头 ▲▼ 指示；再次点击切换/取消。
2. **筛选**：筛选条 = 模块下拉（数据来自 buildTree 聚合）+ 类型多选 + 重用度 + "仅看未确认"开关，与 `#q` 搜索**叠加 AND**；筛选 0 命中时表格区显示空态组件（见 §5）并给"清除筛选"动作。
3. **批量改**：表头 checkbox 全选**可见行**；选中 ≥1 行时工具条浮现：设重用度/设修改类型/设复杂度/批量标记确认/批量删除（删除需 confirm，seq 不重排仅标记 seq_deleted 以保持引用稳定——渲染层过滤）。批量改一次 `items` 写入 → `render()` 重绘 + `refreshTotals()` + `saveFormState()`。
4. **粘贴导入**：复核页"粘贴导入"按钮 → 弹层 textarea（接受 Excel 复制的 TSV 或 CSV 文本）→ 首行表头自动识别列映射（system/desc/type/reuse/modify 可手动调整）→ 预览 10 行 → 确认追加（seq 续号、cx 默认"中"、ok=false），上限沿用 2000 条防呆。
5. **键盘移动**：↑↓ 焦点行高亮（.cur-row），Enter 切换该行确认，Space 展开判定依据，Ctrl+F 聚焦搜索；输入控件聚焦时快捷键让位（target 为 input/select/textarea 时跳过）。
6. **性能决策**：2000 条上限场景全量重绘 ≈ 数十 ms，**不做虚拟滚动**；若后续超限再议（W014 表格组件化的决策点）。

## 4. 识别依据与 AI 采纳/驳回（FR-1.5）

- 行展开在 basis 之外并列「AI 建议」标记（llm_enabled 时 basis 含模型建议来源，识别响应 meta 透传 `ai_source`）。
- **驳回记录**：用户修改 type/reuse/modify 使其偏离识别建议 → 该行记入"驳回队列"（内存 items 元数据 + saveFormState 持久化）：`{seq, field, from, to, reason?}`；轻量原因选择弹层（类型误判/重用度高估/复杂度不符/其他，可跳过）。
- 驳回队列随 `/api/generate` 的 `hist_items` 一并入库（M1 历史记录可追溯），并提供"沉淀为规则"入口（见 §6）。

## 5. 空态/加载/错误引导统一（FR-1.6）

三个统一组件（纯 CSS+模板函数，无框架）：
- `emptyState(icon,title,desc,actionHtml)`：上传空态 / 复核空态（识别 0 条）/**筛选 0 命中**（含"清除筛选"）/ PERT 空态 / 历史面板空态（已有，替换为此组件）。
- `loadingBox(text)`：统一封装现有 mark/进度条文案。
- `errorBox(msg,retryFn)`：错误文案 + 重试按钮 + "查看诊断指引"链接（帮助页锚点）。
- AC 约束：所有错误态必须含下一步动作按钮。

## 6. 识别规则外置与沉淀（FR-2.9）

1. **规则外置**：`data/recognition_rules.json`：
   ```json
   {"schema_ver":1,"updated_at":"...","rules":[
     {"id":"R-ILF-001","name":"数据结构变更→ILF","scope":"desc",
      "patterns":["(增加|新增|修改|保存|更新).{0,14}(字段|表)"],
      "exclude":["页面|界面|详情|展示"],"type":"ILF","modify":null,
      "priority":10,"enabled":true,"source":"builtin"}]}
   ```
   匹配语义：按 rules 数组序（priority 排序）逐条尝试，`patterns` 任一命中且 `exclude` 全不命中即返回该 type；全部未命中回退默认 EI（保持现状语义）。`guess_modify` 同构外置（独立 rules 组）。
2. **零回归对拍**：内置规则作为 seed 导出后，用 `replay_recognize` 对拍——旧实现与新引擎在 45 条样本 + 历史回放集上结果完全一致后才切换。
3. **引擎改造**：`guess_type` 改为规则表驱动（启动时加载，文件缺失/损坏回退内置链并告警）；识别响应 meta 增加 `rules_version`，历史记录 params 记录（可追溯）。
4. **沉淀链路**：FR-1.5 驳回队列 → 复核页"沉淀为规则"入口（由驳回样本生成 keywords 规则草稿）→ 配置中心新增「识别规则」页（列表/新增/编辑/启停/优先级调整）→ 保存写 rules.json（`/api/rules` GET/POST，模式对齐 /api/config）→ 下次识别生效。
5. **防呆**：规则改动后首次识别在结果 alerts 里提示"识别规则已于 <时间> 更新（v<N>）"。
