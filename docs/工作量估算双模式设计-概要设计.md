# 工作量估算模块双模式升级——概要设计

> 版本：V1.0　|　依据：《工作量估算双模式设计-估算方案.md》　|　模板：《阜新银行-票据系统优化-工作量评估V2.0.xlsx》

---

## 一、系统架构

### 1.1 定位
在现有"工作量估算"模块上增加 **IFPUG / PERT 双估算模式**，复用现有本地 Python 引擎 + 浏览器交互架构，不改动其他模块。

### 1.2 架构分层

```
┌─────────────── 浏览器前端 (frontend/index.html) ───────────────┐
│  工作量估算页 │  双模式切换(IFPUG/PERT)   │  结果展示/下载      │
└────────────────────────┬───────────────────────────────────────┘
                         │ HTTP/JSON
┌────────────────────────▼───────────────────────────────────────┐
│                    应用服务层 (scripts/server.py)               │
│  路由分发 → 模式路由 → 规则引擎 → 模板生成器                      │
│     ┌────────────┐   ┌────────────┐   ┌───────────────┐        │
│     │模式选择器   │   │引擎 engine │   │生成 generate_ │        │
│     │ifpug/pert  │   │(IFPUG计数/ │   │xlsx (套模板)  │        │
│     │            │   │ PERT三值)  │   │               │        │
│     └────────────┘   └────────────┘   └───────────────┘        │
└────────────────────────┬───────────────────────────────────────┘
                         │ 读写
                 ┌───────▼───────┐    ┌──────────────┐
                 │ data/ 持久化   │    │ 母版 xlsx     │
                 │ projects.db    │    │ (阜新V2.0等)  │
                 └───────────────┘    └──────────────┘
```

### 1.3 外部接口关系
- 前端 ↔ 服务：REST/JSON（新增估算模式、三值提交、结果查询）
- 服务 ↔ 模板：openpyxl 读写母版，保公式保样式

## 二、功能结构设计

### 2.1 菜单结构
```
工作量估算
├── 上传需求            （IFPUG 模式入口）
├── 功能点审核          （IFPUG 候选确认）
├── PERT 三值录入       （PERT 模式入口）
├── 估算结果展示
└── 结果下载

配置中心
├── 大模型配置          （识别增强，沿用现有）
└── 估算参数（生产率/每人月工天标准/调节系数）

帮助文档
└── 方法论与算法说明
```

### 2.2 子功能说明
| 子功能 | 说明 |
|---|---|
| 模式选择器 | 页面顶部切换 IFPUG / PERT，切换保留已录入数据 |
| IFPUG 识别链 | 上传 docx → LLM 初识 → 确认 → 计数（复用现有） |
| PERT 录入器 | 按"子系统→小模块→功能描述"组织三值输入表单 |
| 结果展示 | 预期值、标准差、阶段占比、调节后预估值 |
| 模板生成 | 双模式结果统一映射到阜新 V2.0 模板输出 |

## 三、数据模型设计

### 3.1 项目信息表 `projects`
| 字段 | 类型 | 说明 |
|---|---|---|
| id | TEXT PK | 项目唯一标识 |
| name | TEXT | 项目名称 |
| mode | TEXT | 当前模式：ifpug / pert / mixed |
| template | TEXT | 母版路径标识 |
| estimated_at | DATETIME | 估算日期 |
| estimator | TEXT | 估算人 |

### 3.2 功能点记录表 `items`
| 字段 | 类型 | 说明 |
|---|---|---|
| id | INTEGER PK | 自增 |
| project_id | TEXT FK | 所属项目 |
| system | TEXT | 子系统/大模块（映射 B 列） |
| module | TEXT | 小模块（映射 C 列） |
| desc | TEXT | 功能描述（映射 D 列） |
| type | TEXT | IFPUG 类型 EI/EO/EQ/ILF/EIF |
| det | INT | 数据元素数 |
| ret_ftr | INT | 记录/引用元素数 |
| complexity | TEXT | 低/中/高 |
| ufp | INT | IFPUG 权重 |
| basis | TEXT | 判定依据 |

### 3.3 PERT 估算表 `pert_estimates`
| 字段 | 类型 | 说明 |
|---|---|---|
| id | INTEGER PK | 自增 |
| project_id | TEXT FK | 所属项目 |
| phase | TEXT | 阶段（需求/设计/开发…） |
| system | TEXT | 子系统 |
| module | TEXT | 小模块 |
| desc | TEXT | 功能描述 |
| optimistic | FLOAT | 乐观值 O（F 列） |
| most_likely | FLOAT | 最可能值 M（E 列） |
| pessimistic | FLOAT | 悲观值 P（G 列） |
| expected | FLOAT | 预期值 =(O+4M+P)/6 |
| sigma | FLOAT | 标准差 =(P−O)/6 |

### 3.4 估算配置表 `estimate_configs`
| 字段 | 类型 | 说明 |
|---|---|---|
| id | TEXT PK | 配置项键 |
| value | TEXT | 配置值 JSON |
| remark | TEXT | 说明 |

> 核心配置项：`base_productivity`（基准生产率 8.54/10.67/12.80）、`days_per_man_month`（每人月工天标准 20.83）、`hours_per_day`（8）、`adjust_factors`（客户0.06/质量0.06/变更0.05/进度0.06）、`vaf_14`（14 个系统特征因子默认分）。

## 四、接口设计

### 4.1 双模式通用
| 接口 | 方法 | 入参 | 出参 |
|---|---|---|---|
| `POST /api/estimate/mode` | 设置模式 | `{project_id, mode}` | 模式确认 |
| `POST /api/estimate/calculate` | 计算 | `{mode, items 或 pert[]}` | `{total_expected, total_man_month, by_phase}` |
| `POST /api/estimate/generate` | 生成成品 | `{project_id, template}` | `{sid, file_url, report}` |
| `GET /api/estimate/result?s=` | 下载成品 | `sid` | xlsx 文件流 |

### 4.2 IFPUG 专用
| 接口 | 方法 | 入参 | 出参 |
|---|---|---|---|
| `POST /api/recognize` | 识别功能点 | docx+b64+params | 候选清单 JSON（沿用现有） |

### 4.3 PERT 专用
| 接口 | 方法 | 入参 | 出参 |
|---|---|---|---|
| `POST /api/pert/item` | 保存三值 | `{project_id, row}` | 保存后 expected/sigma |
| `GET /api/pert/list` | 取估算项 | `{project_id}` | 估算项数组 |

### 4.4 配置
| 接口 | 方法 | 入参 | 出参 |
|---|---|---|---|
| `GET /api/config` | 读配置 | - | 估算参数（沿用现有扩展） |
| `POST /api/config` | 写配置 | 配置 JSON | 更新确认 |

## 五、UI 原型说明

### 5.1 工作量估算页布局
- **顶部**：模式切换 Tab（IFPUG｜PERT）
- **IFPUG 页签**：沿用"上传 → 审核 → 结果"三步
- **PERT 页签**：
  - 左树：阶段 / 子系统分组
  - 右表：描述 | 乐观 | 最可能 | 悲观 | 预期 | 标准差
  - 底栏：阶段合计、项目合计（人天/人月）
- **模式切换规则**：切换后保留各自已录入数据，不互相覆盖

### 5.2 关键交互
- PERT 输入：O ≤ M ≤ P 校验，违反即时红框提示
- 实时重算：改任一值即刷新该行预期值与项目合计
- 阶段占比：结果页饼图展示各阶段工作量占比，供"估算比例"复核

## 六、异常处理设计

| 异常场景 | 处理策略 |
|---|---|
| 模板格式不匹配 | 生成前校验模板表头/关键单元格，不符返回具体缺失列，不做伪写入 |
| 母版文件缺失 | 提示用户指定母版路径（环境变量 WE_TPL 覆盖），不 500 崩溃 |
| 功能点数据缺失（type/DET 为空） | 标记"待复核"，不参与计数；汇总给出缺失数 |
| PERT 三值非法（O>P 或缺值） | 前端即拦截；后端二次校验返回错误码 |
| LLM 识别未启用 | IFPUG 模式回退纯本地规则识别（沿用现有降级） |
| 生成结果超限（如 >3 系统分无效于本模板） | 明确报错并提示调整子系统数量 |
