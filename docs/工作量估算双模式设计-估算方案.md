# 工作量估算模块双模式升级——估算方案设计

> 版本：V1.0　|　依据模板：《阜新银行-票据系统优化-工作量评估V2.0.xlsx》　|　适用范围：工作量估算模块 IFPUG + PERT 双模式改造

---

## 一、项目概述

### 1.1 目标
将现有"工作量估算"模块从单一估算方式，升级为同时支持 **IFPUG 功能点估算** 与 **PERT 三点估算** 两种模式，并以《阜新银行-票据系统优化-工作量评估V2.0.xlsx》为最终成品输出的字段基准。

### 1.2 范围
- **IFPUG 模式**：需求文档 → 功能点识别 → UFP/VAF/AFP → 按模板输出
- **PERT 模式**：估算项三值（乐观/最可能/悲观）→ 预期工期与标准差 → 按模板输出
- **输出**：以阜新银行 V2.0 模板的结构为成表基准（人天/人月）
- **不做**：破坏现有其他功能模块；商品化报价单排版

### 1.3 现有系统现状
- 已有 `frontend/index.html`"工作量估算"菜单，当前为**引擎直连 IFPUG 单模式**（上传 → 审核 → 生成）。
- 现有 `scripts/engine.py` 已实现 IFPUG 五类计数、复杂度矩阵、US/工作量/费用链路。
- 现有代码结构：`server.py`（HTTP 服务）+ `engine.py`（规则引擎）+ `generate_xlsx.py`（模板生成）。

## 二、IFPUG 估算设计

### 2.1 功能点识别规则（如何判定 EI/EO/EQ/ILF/EIF）
按 IFPUG 官方规范，对每条需求/功能描述判定唯一的类型：

| 类型 | 判定要点 | 典型场景 |
|---|---|---|
| **EI** | 数据进入系统，产生新增/修改/删除 | 录入、修改、删除、导入、报文接收处理 |
| **EO** | 数据离开系统，且含派生/加工逻辑 | 报表、数据报送、加工口径输出 |
| **EQ** | 数据离开系统，仅检索无派生业务逻辑 | 纯查询、明细展示、模板下载 |
| **ILF** | 本系统维护的数据文件/表 | 新增或修改的数据表、主数据 |
| **EIF** | 被本系统引用、但由外部维护的数据 | 调用外部系统数据 |

> 识别由现有 LLM 识别层 + 人工复核完成；判定依据写入候选清单供审计。

### 2.2 复杂度分级标准（低 / 中 / 高）
按类型取"维度"计数后查 3×3 阈值矩阵：

| 类型 | 关键维度 | 低 | 中 | 高 |
|---|---|---|---|---|
| ILF / EIF | 数据元素(DET) | [1,19] | [20,50] | ≥51 |
| ILF / EIF | 记录元素(RET) | 1 | [2,5] | ≥6 |
| EI | 数据元素(DET) | [1,4] | [5,15] | ≥16 |
| EI | 引用文件(FTR) | [0,1] | 2 | >2 |
| EO / EQ | 数据元素(DET) | [1,5] | [6,19] | ≥20 |
| EO / EQ | 引用文件(FTR) | [0,1] | [2,3] | ≥4 |

### 2.3 未调整功能点 UFP 计算
按复杂度映射权重：

| 类型 | 低 | 中 | 高 |
|---|---|---|---|
| ILF | 7 | 10 | 15 |
| EIF | 5 | 7 | 10 |
| EI | 3 | 4 | 6 |
| EO | 4 | 5 | 7 |
| EQ | 3 | 4 | 6 |

`UFP = Σ(每条功能点的类型权重)`

### 2.4 价值调整因子 VAF 计算
`TDI = Σ 14 个系统特征因子（SYS1~SYS14）的评分（0~5）`，随后：
`VAF = 0.65 + 0.01 × TDI`

### 2.5 最终功能点 AFP
`AFP = UFP × VAF`

### 2.6 功能点到工作量转换（人月/人天）
`工作量(人天) = AFP × 基准生产率(人时/FP) ÷ 8`

基准生产率取管理层可配置三档（下限/中值/上限），系统默认中值；随后：
`工作量(人月) = 工作量(人天) ÷ 每人月工天标准(20.83)`

## 三、PERT 估算设计

### 3.1 触发场景
- 需求为**变更/迭代型**，功能点难以精确计数；
- 依托专家既有经验直接估算工作量，而非逐条数功能点；
- 用户选择"PERT 模式"或模板类型为 V2.0（阜新银行型）时默认启用。
- 双模式可在同一项目内**混合**使用：确定性模块用 IFPUG，不确定性模块用 PERT。

### 3.2 三值输入字段定义
每条估算项需录入三个值（单位：人天）：

| 字段 | 含义 | 说明 |
|---|---|---|
| 乐观值（O） | 一切顺利的最短耗时 | 模板 F 列"最小" |
| 最可能值（M） | 正常情况的最可能耗时 | 模板 E 列"最可能" |
| 悲观值（P） | 含风险的最长耗时 | 模板 G 列"最大" |

### 3.3 预期工期与标准差公式

预期工期（PERT 加权平均）：
`预期值 = (O + 4M + P) / 6`

标准差（衡量不确定性）：
`标准差 σ = (P − O) / 6`

> 模板 H 列公式 `=(MIN(E:G)+MAX(E:G)+4*(SUM(E:G)-MIN(E:G)-MAX(E:G)))/6` 即 `(P+O+4M)/6`，与标准 PERT 一致。

### 3.4 结果展示方式
- 每条估算项显示 **预期值**，并可展开查看三值与标准差；
- 汇总区显示 **合计最理想值 / 实际预估值** 两档（人天与人月双单位）；
- 分阶段（需求 / 设计 / 开发 / 实施 / 公共 / 维护）占比饼图，便于比例复核。

## 四、与现有模板的映射关系

以下为阜新银行 V2.0 模板列 ↔ 系统字段对应：

| 模板位置 | 模板列/单元格 | 含义 | 系统字段 |
|---|---|---|---|
| B5 表头 | B 列 | 产品/子系统/大模块 | `system`（子系统） |
| C 列 | 小模块/功能单元 | 子任务分组 | `module`（小模块） |
| D 列 | 功能单元/业务单元描述 | 功能描述 | `desc`（功能描述） |
| E 列 | 最可能 | 最可能人天 | `pert.most_likely` |
| F 列 | 最小 | 乐观人天 | `pert.optimistic` |
| G 列 | 最大 | 悲观人天 | `pert.pessimistic` |
| H 列 | 最终估算值 | PERT 预期人天（公式） | `pert.expected`（引擎计算） |
| I 列 | 估算比例 | 人月占比 = H/20.83/H40 | `man_month` |
| B6/D7 | 阶段行 | 需求分析/设计/开发… | `phase`（阶段归属） |
| E36~E39 | 调节系数 | 客户/质量/变更/进度 | `adjust_factor` 配置 |

对应关系说明：
- **IFPUG 模式**下，功能点转换出的工作量会填入 E/F/G 三值（三值=同一中值或按档位拆分），H 列由公式自动算 PERT 预期，使双模式在同一张模板上兼容输出。
- **每人月工天标准** = 20.83（模板名称管理器宏变量），引擎引用同名参数。

## 六、双模式统一的输出约定

- **计量单位**：整车系统统一"人天"录入、"人月"汇总（1 人月 = 20.83 人天 = 166.64 人时）。
- **阶段划分**：需求分析 / 系统设计 / 开发研发 / 实施 / 公共&远程投入 / 现场维护，与模板阶段行一致。
- **调节系数**：客户配合 0.06、质量 0.06、范围/需求变更 0.05、进度 0.06；最终 `实际预估值 = 最理想值 × (1 + Σ调节系数)`。
- **校验**：I 列"估算比例"各阶段占比应处于合理区间，超界提示人工复核。

## 七、风险与对策

| 风险 | 对策 |
|---|---|
| 需求不确定，功能点计数主观 | 提供 PERT 三值修正通道，双模式混合 |
| 模板版本/字段更替 | 模板列映射声明式配置，改配不改码 |
| LLM 识别误判类型 | 强制人工审核 + 判定依据留痕 |
| 三值录入不合理（如 O>P） | 录入校验拦截并提示 |
