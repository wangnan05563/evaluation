# 设计-多语言边界：交付物文案恒为中文（T01669 产品决策）

> 决策日期：2026-10-09　来源任务：T01669（FR-ENG05 链，源头 T01526/T01556）
> 状态：**已裁决并固化**——本文件是该边界的外部权威口径。

## 决策

**交付物（导出件）文案不随界面语言切换，恒为中文。**

覆盖范围（当前全部导出通道）：

| 导出件 | 代码位置 | 中文内容 |
| --- | --- | --- |
| IFPUG 成品造价表（.xlsx） | 后端 `scripts/generate_xlsx.py` 按行业模板生成 | 表头、sheet 名、国标口径字段 |
| PERT 成品表（.xlsx） | 后端同上（PERT 模板） | 表头、sheet 名 |
| 版本对比 CSV | `frontend/src/js/08_m1_fr_1_1_1_8_估算历史_列表_重开.js` | 表头 `类型,功能点,系统,变化摘要`、文件名前缀 `版本对比_` |
| 版本对比 MD | 同上 | 小节 `## 新增 / ## 删除 / ## 变更` |
| 结果摘要 MD | `frontend/src/js/03_m2_fr_1_2_1_3_结果页图表摘要_导出.js` | 正文模板（含「国标造价（GB/T 36964-2018）」整段） |

## 理由（对应任务里四个澄清问题的裁决）

1. **交付物给谁看**：成品表交付甲方/存档/审计，行业既有流程按中文固定模板对接；
   界面语言是操作者个人偏好，两者受众不同，不应联动。
2. **不弹语言选择**：导出即交付物，交互面（界面）已按操作者语言呈现；交付物格式
   统一恒为中文，避免同一项目在不同操作者手里产出两套语言的存档。
3. **表头不得偏离行业模板**：国标成品表表头是行业固定格式，改英文表头会破坏甲方
   既有解析/归档流程——这是决定性约束。
4. **数据域枚举值不译**：`低/中/高`、`新增/修改/删除`、`GB/T 阶段名`、费率领域/
   应用/团队、模板名是**业务数据口径**而非界面文案。它们以中文存库（pert.db、
   history、rates），翻译显示会导致「英文界面下导出的数据与库内数据、重开/对比/
   筛选条件不一致」——比对链路会静默失效。

## 与界面 i18n 的隔离

- 界面文案字典 `data/i18n/{zh-CN,en-US}.json` **不收录**交付物文案；不建 `export.*`
  键命名空间（无需求就没有维护负担）。
- `tests/ui_i18n.mjs` 的英文态全页扫描（S12）扫描的是 DOM 界面文本；交付物内容
  生成到文件、不进 DOM，天然不在扫描范围。此为**设计使然**，不是扫描巧合——
  后续若把导出预览渲染进 DOM，必须把交付物模板节点显式登记为排除项。
- `tests/i18n_check.py` 校验范围同样是界面字典；交付物模板（`generate_xlsx.py`
  表头、前端导出 JS 的 MD/CSV 模板）不参与 i18n，**后续批次不得为其加 data-i18n
  标注或 t()/tf() 调用**（加即破坏「交付物恒为中文」口径）。

## 若未来需要英文交付物（预案，当前不实施）

1. 后端导出接口加 `lang` 参数（独立于界面语言），模板文件双语各一份（`tpl/` 按语言分目录）；
2. 数据域枚举值在导出层做「口径不变、显示映射」，库内存储永不变更；
3. 交付物英文模板需与甲方逐一确认表头格式，不得自行机翻。
