## 3. 关键决策

1. **入口**：`package.json` 增 `scripts.test = "node tests/run.mjs"`；`npm test` 一条命令；支持 `npm test -- --only=unit,api` 分层执行与 `--with-flaky` 开启不稳定套件。
2. **UI 驱动选型**：沿用 **CDP 直连无头 Chrome**（零新增依赖、骨架已稳定跑通全部用例），**不引入 Playwright**（等效覆盖，避免重写 5 个稳定套件的回归风险；HLD 的 Playwright 记为可选演进——若切换，用 `playwright-core + channel:'chrome'` 不下载浏览器）。
3. **双层运行时**：node（编排器 + UI CDP 套件）+ python（规则单测/API 冒烟，系统 Python 直用，无需 venv——仅标准库）。
4. **隔离**：每套件独立 `WE_DATA=临时目录` + 固定端口段（API 8032 起、CDP 9334 起）；编排器负责进程起停与端口回收（收编本轮"双监听孤儿"教训：起前查端口、退后强杀子树）。
5. **夹具**：`data/testdocs/`（已稳定化，不再放 %TEMP%）；识别样本 `data/candidates_replay.json`。
6. **报告**：console 实时 PASS/FAIL + `logs/test_report_<时间戳>.md` 汇总（套件/用例/耗时/失败详情）；任一套件失败退出码 1。

## 5. 编排器行为（tests/run.mjs）

```
npm test
  → 预检：端口 8032/9334 空闲（占用即失败并提示进程号）
  → S1/S2 顺序执行（python，逐套件独立 WE_DATA）
  → 起 S3 隔离实例 → S3 → 停（强杀子树）
  → 起 Chrome(9334, 独立 profile) + S4 隔离实例 → S4 → S5 → 停
  → 汇总报告写 logs/test_report_<ts>.md
  → 全绿退出 0，否则 1
```
